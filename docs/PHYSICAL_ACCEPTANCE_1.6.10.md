# StudyNest 1.6.10 phone acceptance checklist

Automated JVM/Robolectric native-render tests are simulations, not physical-phone tests. Use the final signed APK over the existing 1.6.9 installation. Do not uninstall or clear data.

1. Before/after installation compare History, tasks, saved Wi-Fi networks, monitoring selections, permissions, goal/streak thresholds and theme. The package, signing certificate and Room schema remain unchanged.
2. With a 2-hour goal, verify 1h45 Actual plus 30m Distraction gives 1h45 and 87.5%, incomplete. At exactly 2h Actual the goal completes. Streaks must use Actual with their separate configured minimum; distraction must not earn a streak.
3. During an active library session, open a selected distracting app with Usage Access enabled. After the existing usage-detection cadence, Home's daily Actual timer/goal should stop gaining time, while Distraction and legitimate Library Time continue. Return to an allowed app and verify Actual resumes. Compare History/notification library Actual for the same day, allowing existing refresh latency.
4. Complete a 60-minute Actual session and start a new 30-minute Actual session that day. Home must show 1h30, not 30m. With 20m and 10m distraction in those respective sessions it must still show 1h30. End the second session: the earned daily timer stays 1h30.
5. Earn 2h Actual, end that session, then start a fresh automatic session. Home starts from 2h; after 10m valid focus it shows 2h10. Confirm valid manual study outside the library also contributes to Home/goal/streaks. History and notification library metrics intentionally exclude that outside portion.
6. Close/reopen StudyNest and lock/unlock the phone after earning 2h15. The daily Home total must persist. Also test normal service/process recovery; do not force-stop and expect Android background execution to continue while force-stopped.
7. Across local midnight, Home/goal show the new day's Actual, initially zero if none. An ongoing session keeps its identity and splits accounting at local midnight. Yesterday's History remains intact. Check outside-library manual study and an away/grace interval crossing midnight separately.
8. In Settings → App Monitoring, search wha (or another installed short app name), change an unsaved selection, then tap How App Monitoring works. The first explanation should appear immediately, including on a small/large-font screen. Scroll normally to read the rest; collapse, then verify the query and selection remain. Only Save Changes persists the draft. Repeat with the keyboard open and large font/display scaling on your phone.
9. Confirm existing manual Pause/Resume, locked-screen monitoring, 90-second temporary departure/pause/sound restoration, same-visit reconnection before 30 minutes, finalization after full grace, 45-minute Break Reminder, vibration, notification actions, graphs/Calendar/search/themes/permission recheck and normal battery use remain satisfactory.

Unknown usage must never fall back to gross elapsed time. Android/OEM deep idle, permission/channel restrictions and force-stop can delay or prevent execution; no new bypass or polling was added. Record exact times, permission state and Home/History/notification screenshots if a new problem occurs. The October 3 historical missing-session display cause remains unresolved; no repair was performed.
